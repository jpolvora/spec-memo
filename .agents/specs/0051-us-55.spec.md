# Specification — memo sync --all partial failure: vault-git pull --rebase dies on dirty tree; hybrid AC6 throw aborts whole changeset

## Description

`memo sync --all` in hybrid + vault-git (batched) mode reports partial failure on every real run while `--dry-run` looks healthy. Two independent defects, one per sync channel:

1. **Vault-git channel (`src/vault.ts` `flushVaultGit`):** after the local flush commit, `git pull --rebase origin <branch>` runs against a tree that concurrent daemon writers (stdio MCP `memo serve`, `:3124` status companion, debounced hybrid pushes, session tracking) re-dirty within seconds (compiled views, logs). The pull aborts with `cannot rebase: You have unstaged changes`, the push never runs, and the gitea remote stays frozen while local flush commits accumulate.
2. **Hybrid channel (`src/sync.ts` `applyChangeset` via `src/capture-ignore.ts` `sanitizePathPatterns` AC6):** one incoming record whose `pathPatterns` are fully covered by builtin ignore rules throws `Safety violation: all pathPatterns match ignored paths`, aborting the whole transactional changeset (rollback) so `pulled applied=0 / pushed applied=0` and `syncDual` reports `ok=false`. Live evidence shows 18 offenders sharing one trait: absolute Windows paths from other hosts (`C:/...`, backslash-rooted `\src/...`) that resolve outside the receiving product root. `--dry-run` skips the upsert path, so the failure only appears on real sync.

Scope is the sync data path only: vault-git pull hardening, sync-context skip-and-log for AC6 offenders, per-record accounting, and regression tests. Direct-capture strictness (local `upsert` still throws AC6) stays unchanged, as do conflict strategies, cursors, and auth.

## Acceptance Criteria

- AC1: `flushVaultGit` runs `git pull --rebase --autostash origin <branch>` so a dirty tree re-dirtied after the flush commit no longer aborts the pull; pull succeeds when remote has no divergence and autostash round-trips local modifications.
- AC2: Vault-git channel stays fail-open with accurate state: `writeVaultGitState` records `dirty` / redacted `lastError` / `lastSyncAt`, `result.ok` is true only when pull and push both succeed (remote configured), and no secrets leak into messages.
- AC3: `applyChangeset` never aborts a whole changeset on one AC6 offender: the offending record is skipped and logged with its record id, all other records apply normally, and the result reports `skipped >= 1` with the offender identifiable in logs or `conflictDetails`.
- AC4: A changeset containing 1 AC6 offender plus N valid records yields `applied=N`, `conflicts=0` (unless real conflicts exist), and `syncDual`/`syncHybrid` reports `ok=true` for the hybrid channel.
- AC5: New regression tests exist: dirty-tree-during-pull in `src/vault-git-hybrid-sync.test.ts`; AC6-offender changeset in `src/sync.test.ts` or `src/reconcile.test.ts` asserting skip-and-continue semantics.
- AC6: Direct local `upsert` capture path still throws AC6 for fully-ignored `pathPatterns` (strictness preserved outside sync context).
- AC7: `memo sync --all --dry-run` and real `memo sync --all` agree on success for the same vault state (no dry-run-only green).

### Bug 1 — vault-git

`flushVaultGit` (`src/vault.ts`) commits (`git add -A -- projects config.json .gitignore`), then runs `git pull --rebase origin master`. Concurrent writers rewrite compiled views/logs seconds after the flush commit (observed: flush commit at 18:20:47, 13 files re-dirtied at 18:20:53), so the pull always sees unstaged changes and the push never runs.

### Bug 2 — hybrid AC6

Pull → `applyChangeset` (`src/sync.ts`) → `upsertRecord` (4 call sites) → `sanitizePathPatterns` (`src/capture-ignore.ts`) throws when a record's patterns are fully covered by builtin ignore rules (`dist/`, `build/`, `node_modules/`, `.env`, `*.sqlite`, …). One offender aborts the whole transaction (rollback) → pulled=0/pushed=0, `syncDual` reports `ok=false`. Misleading: `--dry-run` succeeds (skips upsert path).

### Reporter comments (verbatim, condensed)

Root-cause update (Bug 2): pulled live changeset from remote daemon (POST /api/sync/pull: 2676 records, 2968 deletions), evaluated every record through the installed dist's own `sanitizePathPatterns`. 18 offenders, all absolute Windows paths from other hosts resolving outside the product root: one `log-*` record with `C:/Users/.../session-tracking.mdc`, 16 traps with backslash-rooted patterns like `\src/sync.ts`, and one backfill record with absolute `.cursor/plans/*.plan.md`. Conclusion: path-portability problem plus strictness problem; fix direction stands (skip-and-log in `applyChangeset` sync context), plus consider normalizing absolute patterns at capture time.

Vault-git heal status: healed at data level without code changes (committed pending views, clean rebase, pushed to gitea). The `--autostash` hardening is still wanted for the recurring race.

Non-root-cause notes: `error.logs` shows only `:3124` EADDRINUSE WARNs (duplicate status-companion owner, fail-open noise); `memo doctor --dry-run` healthy with 1002 records indexed.

### Design Intent

- `git pull --rebase` without `--autostash` was the intentional simple path for a quiesced vault; it was never designed for the batched-mode reality where two daemon writers re-dirty compiled views seconds after the flush commit. The gap is accidental concurrency drift, not an intentional constraint. Fix preserves intent (rebase linear history) while tolerating the race.
- AC6 strict throw in `sanitizePathPatterns` is intentional for the direct-capture path (reject junk/ignored patterns at write time). Applying the same abort to inbound cross-machine sync records is the accidental gap: absolute host paths do not survive portability, and one bad record must not veto thousands. Fix keeps capture strict, relaxes only the sync-apply context to skip-and-log.
