# Specification — memo setup: add --host dsh (DeepSeek Harness 0.2) MCP wiring

## Description

Add a first-class `dsh` host target to `memo setup` so spec-memo can be wired into a DeepSeek Harness (DSH 0.2) profile as an MCP server. The current `memo setup --host` allowlist (`cursor | vscode | opencode | antigravity | claude | generic`) has no DSH path, and the `generic` JSON `mcpServers` block is not readable by DSH, which composes its plugin tree from YAML loader patch entries in a profile patch layer.

Technical scope: extend `src/types.ts` `HostName`, `src/setup.ts` (`SUPPORTED_HOSTS`, `resolveHostConfigPath`, `generateHostMcpSnippet`, `writeHostMcpConfig`, `runSetup`), and `src/cli.ts` setup flags (`--host`, `--profile`, `--project-root`, `--transport`, `--print-mcp`, `--write-mcp`) to emit and merge exactly one DSH insert patch mounting `@deepseek-ai/dsh-mcp-client` (bundled in DSH 0.2, no install required). The stdio entry carries `{ serverName, transport: stdio, command, args, cwd }` with the mandatory `insert:` wrapper targeting `mcp-<serverName>`; the `streamable-http` entry carries `{ serverName, transport, url, headers }` with Authorization resolved from `process.env.SPEC_MEMO_AUTH_TOKEN` via a `!!js` expression. `cwd` binds the spawned server to the resolved project root because `memo serve` resolves project identity from the working directory with no project/root flag override. Writes merge only into `$DSH_HOME/profiles/<profile>/cordis.patch.yml` (create-as-array when absent, append-or-replace by `mcp-<serverName>` id, byte-for-byte preservation of unrelated entries), verify via `dsh --profile <p> --patch <file> --dump-config` (fail on `entry "mcp-<serverName>" not found` or missing composed entry), and are idempotent. Update the host matrix docs. Touchpoints: setup/host snippet pipeline, YAML serialization for the patch file, DSH profile discovery (`$DSH_HOME`, default `~/.dsh`), CLI validation, `deployment-modes` / setup test suites.

## Acceptance Criteria

- AC1: When print-mcp runs with `--host dsh`, the setup shall print a YAML list of exactly one patch containing `insert:` with one `@deepseek-ai/dsh-mcp-client` entry including serverName, transport stdio, cwd, command and args.
- AC2: When write-mcp runs with `--host dsh --profile <p>`, the setup shall create or merge `$DSH_HOME/profiles/<p>/cordis.patch.yml` preserving every unrelated entry byte-for-byte.
- AC3: When post-write verification runs `dsh --profile <p> --patch <file> --dump-config`, the setup shall report success only when the composed tree contains the inserted entry and stderr has no `not found` warning.
- AC4: When a bootstrap call flows through the registered server with a resolved project root, the server shall return the workspace project id with its trap count instead of a `local-*` fallback.
- AC5: If write-mcp runs a second time with identical inputs, then the setup shall change nothing and report `already configured` without duplicating the id or reordering entries.
- AC6: The setup shall leave `--host generic` output unchanged with no host regression.
- AC7: The setup shall never modify `cordis.yml` or `package.json` during print or write flows.
- AC8: When `--transport streamable-http` is selected, the setup shall emit a serverName, transport, url and headers entry whose Authorization header reads `process.env.SPEC_MEMO_AUTH_TOKEN` via a `!!js` expression.
- AC9: When no project root can be resolved, the setup shall warn that vault operations will bind to a fallback project instead of silently writing an entry without `cwd`.
- AC10: The docs shall include a DSH row in the host matrix noting the plugin ships inside DSH 0.2 or later with no package install required.
- AC11: If the profile name or project-root path is invalid, then the setup shall fail with a named error before writing any profile file.
- AC12: If the `dsh` CLI is unavailable during verification, then the setup shall fail with a named error instead of reporting success.

## Original Issue Context

## Summary

`memo setup --host` accepts `cursor | vscode | opencode | antigravity | claude | generic`, but not **DeepSeek Harness (DSH)**, so there is no supported path for wiring the `spec-memo` MCP server into a DSH profile.

The `generic` target cannot be used as a workaround: it emits a JSON `mcpServers` block, and DSH does not read that shape. DSH composes its plugin tree from YAML **loader patch entries** in a profile, and adding a new plugin requires the `insert:` wrapper described below.

Request: add a first-class `dsh` host target that emits — and optionally merges — a DSH profile patch entry mounting `@deepseek-ai/dsh-mcp-client`.

| CLI | `dsh --profile <name>`, `dsh plugin --profile <name> add <pkg>`, `dsh --patch <file>`, `dsh --dump-config`, `dsh --profile <p> --dump-config-schema` |

## Why `generic` does not work

`memo setup --print-mcp --host generic` emits:

```json
{ "mcpServers": { "spec-memo": { "command": "memo", "args": ["serve"] } } }
```

DSH has no `mcpServers` reader. It mounts **one `dsh-mcp-client` instance per MCP server** by *inserting* an entry into the profile's patch layer. The `insert:` wrapper is mandatory, because the loader treats a patch entry without `insert` as an id-targeted override of an existing entry, and an unknown id is only **warned and skipped**:

```console
$ dsh --profile web --patch ./overlay.yml --dump-config
dsh: [./overlay.yml] patch: entry "mcp-spec-memo" not found
```

That warning goes to the stderr of a CLI invocation a GUI user never runs, so a wrong shape fails completely silently. The correct form:

```yaml
- insert:
    - id: mcp-spec-memo
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: spec-memo
        transport: stdio
        command: memo
        args: ['serve']
        cwd: /absolute/path/to/the/project
```

Per the loader schema, *"an insert appends entries, optionally inside the group identified by id"*, and *"unknown targets and non-insert patches without a nonempty id are warned and skipped."*

Tools then surface to the model as `mcp__spec-memo__<rawName>`. `serverName` must match `[A-Za-z0-9_-]{1,32}`, so the configured `mcpServerName` (default `spec-memo`) maps cleanly.

## Project binding: `cwd` is not optional

`memo serve` resolves the vault project from the **working directory** (git remote → project id). It has no project or root flag (`--help` offers only `--sse`, `--port`, `--host`, `--status`, `--status-port`, `--no-status`, `--auth-token`, `--vaultRoot`, `--json`), and there is no project-identity environment override (`SPEC_MEMO_ROOT` selects the vault, not the project).

A host that spawns MCP servers once per application composition, with the application's own working directory, therefore binds every session to an empty fallback project. Observed on a host whose workspace is a git repo with 510 vault records:

```json
{ "projectId": "local-desktop-4151651c", "gitRemote": null, "traps": [], "totalTrapsCount": 0,
  "notices": ["Hybrid sync pull notice for 'local-desktop-4151651c': Remote sync pull failed with HTTP 401: Unauthorized"] }
```

The same command run from the workspace root resolves `github.com-<owner>-<repo>` with 161 traps. Since the harness prefers MCP over the CLI for its memory reads once the server is registered, a missing `cwd` silently degrades memory to "no traps found" rather than failing loudly. Whatever `--host dsh` emits must therefore either carry an explicit project root or refuse to report success without one.

## Requested behavior

1. `memo setup --host dsh [--profile <name>] [--project-root <path>]`.
2. `--print-mcp` prints the YAML patch entry above (not JSON), including the mandatory `insert:` wrapper, ready to paste into `cordis.patch.yml`.
3. `--write-mcp` merges exactly that one insert patch into `$DSH_HOME/profiles/<profile>/cordis.patch.yml`: create the file as a top-level YAML array when absent, append when no `insert` patch already carries the `mcp-<serverName>` id, replace in place when present, and **never** modify `cordis.yml` or `package.json`.
4. Emit `cwd:` from the resolved project root. When no root can be resolved, warn that vault operations will bind to a fallback project instead of silently writing an entry without it.
5. Verify before reporting success: run `dsh --profile <profile> --patch <file> --dump-config` and fail when stderr reports `entry "mcp-<serverName>" not found` or the entry is missing from the composed tree. A write that only produces a warning must not be reported as configured.
6. `--transport streamable-http` maps to a `{ serverName, transport: 'streamable-http', url, headers }` entry, where the Authorization header is filled by a `!!js` expression reading `process.env.SPEC_MEMO_AUTH_TOKEN` (DSH resolves `!!js` expressions at load time). The explicit `env`/`headers` layer is required because the harness scrubs credential-shaped names (`/KEY|PASSWORD|SECRET|TOKEN/i`) from every child environment before the explicit layer merges.
7. Idempotent: a second `--write-mcp` run changes nothing and reports `already configured`.
8. Documentation: a DSH row in the host matrix, plus a note that the plugin ships inside DSH ≥ 0.2, so no package install is required.

### Design Intent

- The 6-entry host allowlist is an intentional constraint: each host needs an explicit snippet shape and config path, so unknown hosts are rejected rather than guessed. The gap is accidental omission (DSH 0.2 postdates the list), not a deliberate refusal.
- `git log -p -S "SUPPORTED_HOSTS"` shows incremental host additions with per-host snippet branches; the DSH change follows that established pattern (new union member + snippet branch + path + merge/verify), not a redesign of the setup pipeline.

## Notes

- `serverName` must match `[A-Za-z0-9_-]{1,32}`; the configured `mcpServerName` (default `spec-memo`) maps to patch id `mcp-<serverName>` and tool prefix `mcp__<serverName>__*`.
- The `insert:` wrapper is load-bearing: a patch entry without `insert` and with an unknown id is warned and skipped by the DSH loader, failing silently for GUI users.
- `cwd` is required for correct project binding; without it every session binds the fallback project and memory reads degrade to zero traps.
- `streamable-http` must not persist tokens: Authorization flows only through the `!!js` expression reading `process.env.SPEC_MEMO_AUTH_TOKEN` at DSH load time, surviving the harness child-environment credential scrub.
- Windows spawn: `command: memo` relies on `cross-spawn` shim resolution for `memo.cmd`; document the absolute-path fallback for hosts that spawn without it.
- Stack invariants (typescript-node): strict types with no unchecked `any`, zero floating promises, schema validation on CLI/profile/path boundaries, path containment on the profile merge, stream/descriptor cleanup in `finally`.
