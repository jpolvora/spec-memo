# Specification — Relocatable consumer hub data

## Description

Decouple consumer knowledge hub storage (`MEMORY.md`, `memory/*`, and agent changelog) from hardcoded in-tree `{sharedDir}` locations in consumer workflows (e.g. `workflow-skills`). Allow the memory hub root to resolve dynamically to `$SPEC_MEMO_ROOT/projects/<projectId>/` or an external vault path.

Greenfield feature. Design Intent skipped: Phase 2 harness adapter specification.

## Acceptance Criteria

- AC1: Consumer workflow configuration allows specifying an external `{memoRoot}` or vault directory for memory hub data.
- AC2: When `{memoRoot}` is configured, memory read/write operations resolve files to the vault rather than writing to in-repo `.agents/skills/ws-shared/memory/` or `MEMORY.md`.
- AC3: Agent changelog entries generated by workflows append to the vault `logs/` store instead of mutating a committed changelog in the product working tree.
- AC4: Git status in the consumer product repository remains clean after recording anti-regression traps and workflow completions.

## Original Issue Context

PRD Phase 2: Relocatable consumer hub (MEMORY / changelog). Decouple consumer hub data from in-tree `{sharedDir}`.

## Notes

- Implemented primarily as harness updates in consumer skills (`ws-self-learning`, `ws-changelog`).
- Depends on Phase 1 vault layout and MCP/CLI interfaces.

## Out of Scope

| Feature | Reason |
|---------|--------|
| In-repo fallback files | The target is zero required in-repo workflow files |
| Multi-tenant server syncing | Local vault handles per-machine storage |
