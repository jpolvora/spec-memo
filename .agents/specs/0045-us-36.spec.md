# us-36 — memo setup --host opencode emits invalid MCP config

## Problem
`memo setup --host opencode --print-mcp` (v0.17.0) emits a snippet that fails OpenCode config validation:

```json
{
  "mcp": {
    "spec-memo": {
      "type": "stdio",
      "command": "memo",
      "args": ["serve"]
    }
  }
}
```

Two problems vs authoritative schema https://opencode.ai/config.json (`#/$defs/McpLocalConfig`):

1. `type` must be `"local"`, not `"stdio"`. Schema enum is `["local"]` for `McpLocalConfig` / `["remote"]` for `McpRemoteConfig`. `"stdio"` is rejected.
2. `command` must be an **array of strings** (e.g. `["memo", "serve"]`), never a single string + separate `args` array. `args` is not a known property (`additionalProperties: false`).

Copy-pasting breaks `opencode.json` on startup (`ConfigInvalidError`).

## Original Issue Context
- spec-memo 0.17.0, Windows 11, vault `C:\Users\jpolv\.spec-memo`
- Working schema-compliant entry verified via `opencode mcp list`:
```json
"mcp": {
  "spec-memo": {
    "type": "local",
    "command": ["memo", "serve", "--vaultRoot", "C:\\Users\\jpolv\\.spec-memo"],
    "enabled": true,
    "environment": { "SPEC_MEMO_ROOT": "C:\\Users\\jpolv\\.spec-memo" }
  }
}
```
- Minimal `command: ["memo", "serve"]` also works (vault fallback to `$SPEC_MEMO_ROOT` / `~/.spec-memo/`).

## Acceptance Criteria
- AC1: opencode snippet emits `"type": "local"` (never `"stdio"`).
- AC2: opencode snippet emits `"command": ["memo", "serve"]` array form, no `args` key.
- AC3: opencode snippet includes `"enabled": true`; when vault root is non-default, includes `"environment": { "SPEC_MEMO_ROOT": ... }` (and optionally `--vaultRoot` in command).
- AC4: other hosts unchanged — cursor/vscode/claude/antigravity/generic keep `command` string + `args` array shape.
- AC5: `memo setup --host opencode --print-mcp` output validates against opencode `McpLocalConfig` (type enum, command string[], no additionalProperties).
- AC6: unit tests cover opencode shape + regression for other hosts; full suite green.
- AC7: README manual host snippets include opencode example (prevent copy-paste errors).

## Technical Boundaries
- File: `src/setup.ts` → `generateHostMcpSnippet`, `runSetup` vaultRoot wiring.
- Tests: `src/deployment-modes.test.ts` Phase 1 snippet test must assert opencode shape.
- Docs: `README.md` host wiring section; check `docs/arch.md` signature if stale.
- No change to transport (always local stdio spawn `memo serve`), only snippet shape.

## Edge Cases
- Default vault (`~/.spec-memo` / `$SPEC_MEMO_ROOT`): minimal `["memo","serve"]` + `enabled:true`, no env needed.
- Custom `--vaultRoot`: pin via `environment.SPEC_MEMO_ROOT` (+ `--vaultRoot` arg) to match Cursor `mcp.json` wiring.
- `writeHostMcpConfig` merge into existing `~/.config/opencode/config.json` must preserve other `mcp` entries.
- Unsupported host still throws with supported list.
