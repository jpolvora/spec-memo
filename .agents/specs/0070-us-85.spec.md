# Specification — Harden tool inputs: UPSERT_FAILED raw TypeError on object-shaped frontmatter arrays + session_end without session_start

**State:** open

## Description

MCP and CLI tool boundaries must reject or coerce bad inputs before store code assumes arrays, and session close must not treat a missing session as a crash.

`upsert` today can throw `TypeError: (pathPatterns || []).slice is not a function` from `findMatchingTrap` in `src/store.ts` when `pathPatterns`, `tags`, or `linkedPaths` arrive as a plain object. That path runs before structured frontmatter validation. The tool must either coerce (string scalar to a one-item array; plain object to `Object.values`) or return `Invalid record frontmatter: ...` and must not leak an unhandled `TypeError`.

`prompt` `session_end` for a `sessionId` that has no session record must not throw `PROMPT_TOOL_FAILED`. It returns a soft result `skipped: no-session` or creates the session record and ends it. When `sessionId` is omitted and the project has exactly one active session, use that id. When zero or several active sessions exist, return an actionable error that names the requirement and how to pass `sessionId`. `prompt record` without `body` stays an argument error and names `body`.

## Acceptance Criteria

- AC1: `upsert` with `frontmatter.pathPatterns`, `tags`, and `linkedPaths` each set to a plain object (for example `{ "0": "src/**" }`) does not throw `TypeError` and does not log `UPSERT_FAILED` with `.slice is not a function`.
- AC2: That call either stores array values taken from the object's values or returns a structured `Invalid record frontmatter` message that names the fields. Both outcomes are acceptable; a raw `TypeError` is not.
- AC3: A string scalar for `pathPatterns` is stored as a one-element array or rejected with the same structured frontmatter error, never a `TypeError`.
- AC4: `session_end` with a `sessionId` that never had `session_start` returns success with `skipped: no-session` or an ended session record, and does not throw `Cannot end session` / `PROMPT_TOOL_FAILED`.
- AC5: `session_end` with no `sessionId` and exactly one active session for the project ends that session.
- AC6: `session_end` with no `sessionId` and zero or more than one active session returns an error that states `sessionId` is required and that multiple or none are active. It does not pick an arbitrary session.
- AC7: `prompt record` without `body` returns an argument error that names `body`.
- AC8: Regression tests cover object-shaped array fields on upsert and `session_end` without `session_start`. They fail on the current TypeError and hard session error.

## Original Issue Context

## Failure class

Tool-input hardening and idempotency in the MCP/CLI surface, surfaced by the last workflow run (spec `0067`):

1. `upsert` can crash with a raw `TypeError` instead of a structured validation error when a frontmatter array field arrives as an object.
2. `session_end` treats "no session record" as a hard error.
3. `session_end` / `prompt record` reject missing required parameters without inference or an actionable recovery path.

## Expected contract

- No tool may leak an unhandled `TypeError`. Array-typed frontmatter (`pathPatterns`, `tags`, `linkedPaths`) must be either **coerced** (scalar → single-item array; plain object → `Object.values`) or **rejected** with the structured `Invalid record frontmatter: ...` message — never crash mid-path.
- `session_end` on a session that never started is not a fault: make it idempotent (soft `skipped: no-session`) or auto-create the session record. It must not surface as `PROMPT_TOOL_FAILED`.
- When `session_end` omits `sessionId` and exactly one active session exists for the project, infer it; otherwise keep the error but make it actionable.

## Code references

- Crash: `src/store.ts:173` — `const newPatterns = (pathPatterns || []).slice().sort();` in `findMatchingTrap`, plus `src/store.ts:189` for existing records. This runs before the validation at `src/store.ts:483` (`Invalid record frontmatter: ...`), so an object-shaped field escapes as a raw `TypeError`.
- Session close: `src/prompt.ts:285-288` throws `Cannot end session ...`; surfaced at `src/tools.ts:1642` as `PROMPT_TOOL_FAILED`.

## Reproduction shape

- MCP `upsert` with `frontmatter.pathPatterns` as an object (e.g., `{ "0": "src/**" }`) — a common LLM-produced shape — on a project with at least one active trap.
- MCP `prompt` `session_end` with a `sessionId` that never had a matching `session_start`.

## Suggested fix

- Normalize frontmatter array fields at the tool boundary (or guard `findMatchingTrap`) before any array operation; keep the structured validation message as the user-facing error.
- Make `session_end` idempotent (soft-skip or auto-create) and infer `sessionId` when a single active session exists.
- Add regression tests: object-shaped `pathPatterns`/`tags`/`linkedPaths` on `upsert`; `session_end` without a prior `session_start`.

### Design Intent

Structured frontmatter validation already exists later in `store.ts`. The TypeError is an ordering bug: array methods run first. Requiring `session_start` before `session_end` is current control flow, not a product promise that a missing session is an operator fault. Idempotent close matches session lifecycle expectations for agents that end without a recorded start.
