# Specification — doctor: pollution scan ignores .spec-memo-ignore, forcing --fix deletion of live in-tree files; import should be idempotent

## Description

`memo doctor` is unusable as a health gate in consumer repositories that intentionally keep live workflow state in-tree (hybrid mode with dual memory backends). Three independent defects share one blast radius — data loss via `doctor --fix`:

1. **Pollution scan bypasses ignore boundary (`src/doctor.ts` `scanForRepoPollution`):** the scan walks the product tree with hardcoded prefix/suffix rules (`plan_residue`, `memory_residue`, `state_residue`, `telemetry_residue`, `log_residue`) and never consults `loadIgnoreRules` / `isPathIgnored` / `checkCapturePath` from `src/capture-ignore.ts`. A project `.spec-memo-ignore` covering the canonical live dirs (`.agents/plans/`, `ws-shared/memory/`, `MEMORY.md`, `*.state.md`) verifies per path via `memo doctor --check-capture` (`IGNORED (source: .spec-memo-ignore)`), yet the full scan counts the same files. The two code paths disagree on the same boundary.
2. **Unsafe `doctor --fix` (`src/doctor.ts` `runDoctor`):** the only path to `healthy: true` unconditionally `unlink`s every flagged file — including `git ls-files`-tracked curated knowledge (root `MEMORY.md`, `ws-shared/memory/*.md` self-learning traps), live workflow runs the `ws-*` harness requires in-tree (`.agents/plans/` per `plans.dir`), and false positives from over-broad suffix matching.
3. **Over-broad `run.json` suffix rule:** `lowerRel.endsWith('run.json')` matches across filename boundaries, so an IDE artifact such as `Default.abprun.json` is flagged `state_residue`.
4. **Non-idempotent `memo import` (`src/importer.ts`):** re-running import on an unchanged tree after content is already vaulted should be a safe per-record no-op (stable id + content-hash compare → ok/skipped). Anything already in the vault (spec, memory/trap, changelog/log entry) must never duplicate and never throw, so scheduled or repeated imports are safe.

Scope is the doctor / capture-ignore / importer path only: ignore-aware scan, boundary-correct `run.json` matching, tracked-file-safe `--fix`, idempotent import accounting, and regression tests. No changes to vault layout, FTS indexing, sync channels, or conflict strategies.

## Acceptance Criteria

- AC1: `scanForRepoPollution` filters every candidate through the ignore boundary (`loadIgnoreRules` / `isPathIgnored` with `productRoot` plus `projectId` / `vaultRoot`) before pushing a residue item, honoring project `.spec-memo-ignore` and vault `config.json` `projects.{id}.ignorePaths` exactly like `checkCapturePath` does; any path reporting `IGNORED` via `memo doctor --check-capture` never appears in the full-scan result for the same root.
- AC2: `run.json` state matching uses a filename-boundary rule (for example `/(^|[/._-])run\.json$/` on the posix-normalized relative path, case-insensitive like the existing `lowerRel` handling) instead of bare `endsWith('run.json')`, so `Default.abprun.json` and similar cross-boundary names are not flagged while top-level and nested `run.json` still are when not ignored.
- AC3: `memo doctor --fix` never deletes `git ls-files`-tracked files silently: tracked candidates are skipped by default, reported as skipped with their paths, and deleted only under an explicit opt-in (for example `--include-tracked` plus a confirmation listing). Untracked live files covered by ignore rules are already excluded by AC1 and never reach the deleter.
- AC4: Re-running `memo import` on an unchanged tree is idempotent per record: each already-vaulted spec, memory/trap, plan, state, and changelog/log entry resolves via stable record id plus content-hash comparison to ok/skipped — zero duplicates written, zero throws for already-present content, with `totalImported` unchanged and skipped/ok accounting visible in the result.
- AC5: A dual-mode consumer repo (live `.agents/plans/`, `ws-shared/memory/` plus `MEMORY.md`, git-tracked root `MEMORY.md`) with those canonical dirs covered by `.spec-memo-ignore` reaches `healthy: true` from `memo doctor` without deleting anything; the doctor result distinguishes excluded-by-ignore from genuine residue.
- AC6: New regression tests exist: ignore-aware pollution scan (`src/doctor.test.ts` with a planted `.spec-memo-ignore` covering plans/memory/state fixtures), `run.json` boundary test (`abprun.json` clean vs `run.json` flagged), `--fix` tracked-skip test (tracked fixture survives default fix), and import idempotency test (`src/importer.test.ts` or equivalent asserting second-run no-op on the same tree).

### Reporter verbatim (expected behavior)

- The pollution scan honors `.spec-memo-ignore` (plus vault `config.json` `projects.{id}.ignorePaths`) exactly like `--check-capture` does, so dual-mode repos with live in-tree state can reach `healthy: true` without deleting anything.
- `memo import` is idempotent per record id/content-hash: already-vaulted specs, memory entries and changelog/log events report ok/skipped.
- `doctor --fix` never deletes git-tracked files silently (skip tracked paths or require explicit confirmation), and suffix rules don't match across filename boundaries (`abprun.json` != `run.json`).

### Reporter verbatim (suggested fix)

- File: `dist/doctor.js` (`scanForRepoPollution`): filter candidates through `loadIgnoreRules`/`checkCapturePath` before pushing residue items.
- File: `dist/doctor.js` (state rule): match `run.json` on a filename boundary (e.g. `/(^|[/._-])run\.json$/`-style) instead of bare `endsWith('run.json')`.
- Import path: upsert by stable record id; when the vault copy already matches (id + content hash), report skipped/ok instead of duplicating.
- `doctor --fix`: skip `git ls-files`-tracked paths by default (or gate behind an explicit `--include-tracked` + confirmation listing).

### Design Intent

- Hardcoded prefix/suffix matching in `scanForRepoPollution` was the intentional simple path for the single-mode default (no live in-tree state; product git is not a memory store). It was never designed for the dual-backend reality where `.agents/plans/`, `ws-shared/memory/`, and a git-tracked root `MEMORY.md` intentionally stay in-tree while the vault mirrors them. The gap is accidental mode drift, not an intentional constraint. Fix preserves intent (flag genuine residue) while honoring the same ignore boundary `--check-capture` already enforces.
- `doctor --fix` unconditional `unlink` was the intentional fast cleanup for untracked residue in single-mode repos. Applying it to `git ls-files`-tracked curated knowledge is the accidental gap: tracked files are by definition curated, not residue. Fix keeps fix fast for untracked residue and safe by default for tracked paths.
- Bare `endsWith('run.json')` was an intentional loose suffix for workflow state dumps; matching across filename boundaries (`abprun.json`) is the accidental over-match. Fix keeps intent (catch `run.json` anywhere) with a boundary guard.
- Import via `upsertRecord` per file was intentional for first-time migration; per-record id plus content-hash short-circuit for already-vaulted content is the missing idempotency half. Fix preserves first-import behavior and makes repeat runs no-ops.
